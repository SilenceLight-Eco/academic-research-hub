# 审稿任务

左侧“审稿”用于管理自己担任审稿人的任务，不替代论文管线的在投论文。

## 使用

登录后点击“新建审稿”，在右侧完整表单填写稿件名称、期刊、编号、邀请日期、截止日期、提交日期和稿件／审稿系统链接。初始轮次为第 1 轮；状态可选待决定、审稿中、已提交、已拒绝；审稿建议可选接收、小修、大修或拒稿。

分别记录总体评价、主要意见、次要意见、仅供编辑的保密意见及个人备注。日期使用日期选择器。左侧支持检索和状态筛选；待处理任务优先按截止日期排列，7 天内截止和已逾期会显示标识。提醒仅为页面内提示，不发送邮件或系统通知，已提交、已拒绝不再计入截止提醒。

修改沿用工作台三分钟自动保存机制，并在切换任务、切换模块时保存；也可以点击右上角“立即保存”。保存失败保留编辑和本机草稿，不提示成功。较早的保存响应不会覆盖仍在编辑的新内容。

删除先移入回收站，支持恢复；彻底删除须确认，无法恢复。任务包含在账号工作台的云端同步、数据备份预览和跨模块统一检索中；回收站不参与检索。

## 审稿轮次历史

点击稿件名称右侧“开始下一轮”，确认后先保存当前填写的内容，再完整归档本轮稿件信息、日期、意见、建议和个人备注。保存或归档失败不会清空当前内容，也不会开始新轮次。归档成功后轮次加 1，保留稿件名称、期刊、编号和链接；新一轮状态为“审稿中”，建议为“尚未决定”，日期、意见及个人备注清空，方便重新填写。

表单下方“审稿轮次历史”按最新轮次在上排列，默认折叠，展开可只读查看并分别导出作者版和编辑保密版。历史不因后续编辑而改变，随账号同步、刷新、数据备份及回收站恢复保留。历史不能单独修改或覆盖；彻底删除任务会同时删除其历史。已有任务无需数据库迁移，在首次开始下一轮时创建历史。最多支持 20 轮；轮次不再直接修改，以免误覆盖旧意见。延迟到达的旧轮次保存、重复开始同一轮的请求会被拒绝。

## 二审核对清单

表单下方的“二审核对清单”可直接“+ 新建问题”，每条记录问题类型（主要意见／次要意见／补充问题）、待核对问题、作者回应、我的判断及状态（待核对／已解决／部分解决／未解决）。直接在页面填写，不弹出输入窗口；支持删除单条问题，删除有内容的条目需确认。统计即时显示各状态数量，每轮最多 100 条，各文本字段最多 10000 字符。

点击“引用上一轮意见”，从最近归档轮次的主要、次要意见创建条目，标注来源轮次，不引用编辑保密意见、总体评价和个人备注。按行首的编号或项目符号分条，续行保留在同一问题；未编号的整段意见视为一条。导入后请自行核对并修改分条结果，系统不分析作者回应、不自动判断是否解决。重复引用已导入的条目不会重复添加，即使后来改过条目文字。超出数量或单条字数限制时不会部分导入，请手动拆分。

清单沿用三分钟自动保存、切换任务／模块保存与“立即保存”，同步到同一账号；保存失败保留本机草稿。开始下一轮时，本轮清单一并归档为只读历史，新一轮从空清单开始。历史、数据备份和任务回收站恢复均保留清单。清单是内部核对记录，不会加入作者版或编辑保密版导出；需要对外说明时，请自行整理到对应审稿意见字段中。

## 分别导出审稿意见

右上角“导出给作者”下载 Markdown 文件，仅包含总体评价、主要意见和次要意见；“导出给编辑”仅包含审稿建议及编辑保密意见。两份文件都有稿件名称、期刊、编号、轮次，文件名明确区分作者版与编辑保密版。个人备注、审稿系统链接和日期均不导出。没有填写对应内容时会提示先填写，不生成空白意见。

右上角导出读取当前表单，包括尚未同步的修改；历史内导出读取对应轮次的归档意见，不读取当前轮次内容。仅在本机下载，不发送给第三方，不改变任务状态，也不代替“立即保存”。下载后请核对内容和文件名，再自行提交至审稿系统。即使保密字段未导出，也应检查是否误将保密内容填入作者意见。

## 保密与部署

审稿正文保存在当前登录账号的 Supabase 工作台数据中，不发布进 GitHub 源码。需遵守期刊保密政策，不要保存禁止托管到第三方的稿件。此模块不上传稿件文件、不自动抓取稿件、不调用 AI 或外部文献接口、不向编辑／作者发送意见，也不自动改变实际审稿系统的提交状态。

只需发布前端，无数据库迁移或新增 Edge Function。`/api/peer-reviews` 是现有静态接口适配器的工作台读写路径，沿用账号访问控制和保存冲突检测，匿名访问被拒绝。

测试：`node scripts/test-peer-review.cjs`、`node scripts/test-peer-review-ui.cjs`。
