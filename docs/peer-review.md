# 审稿任务

左侧“审稿”用于管理自己担任审稿人的任务，不替代论文管线的在投论文。

## 使用

登录后点击“新建审稿”，在右侧完整表单填写稿件名称、期刊、编号、轮次、邀请日期、截止日期、提交日期和稿件／审稿系统链接。状态可选待决定、审稿中、已提交、已拒绝；审稿建议可选接收、小修、大修或拒稿。

分别记录总体评价、主要意见、次要意见、仅供编辑的保密意见及个人备注。日期使用日期选择器。左侧支持检索和状态筛选；待处理任务优先按截止日期排列，7 天内截止和已逾期会显示标识。提醒仅为页面内提示，不发送邮件或系统通知，已提交、已拒绝不再计入截止提醒。

修改沿用工作台三分钟自动保存机制，并在切换任务、切换模块时保存；也可以点击右上角“立即保存”。保存失败保留编辑和本机草稿，不提示成功。较早的保存响应不会覆盖仍在编辑的新内容。

删除先移入回收站，支持恢复；彻底删除须确认，无法恢复。任务包含在账号工作台的云端同步、数据备份预览和跨模块统一检索中；回收站不参与检索。

## 保密与部署

审稿正文保存在当前登录账号的 Supabase 工作台数据中，不发布进 GitHub 源码。需遵守期刊保密政策，不要保存禁止托管到第三方的稿件。此模块不上传稿件文件、不自动抓取稿件、不调用 AI 或外部文献接口、不向编辑／作者发送意见，也不自动改变实际审稿系统的提交状态。

只需发布前端，无数据库迁移或新增 Edge Function。`/api/peer-reviews` 是现有静态接口适配器的工作台读写路径，沿用账号访问控制和保存冲突检测，匿名访问被拒绝。

测试：`node scripts/test-peer-review.cjs`、`node scripts/test-peer-review-ui.cjs`。
